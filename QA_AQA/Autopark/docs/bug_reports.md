## БАГ-РЕПОРТ #1

### Базовая информация

**ID бага:** `BUG-USER-EMAIL-VALIDATION`  
**Название:** Регистрация пользователя с невалидным email проходит успешно  
**Дата обнаружения:** 2025-10-30  
**Обнаружен:** Directpi  
**Приоритет:** P1 (High)  
**Серьезность:** High  
**Статус:** New  
**Исполнитель:** Не назначен  
**Окружение:** DEV  
**Версия API:** v1  
**Модуль:** Auth / User

---

### Описание

**Краткое описание:**  
При регистрации нового пользователя через эндпоинт `/api/v1/auth/register` система принимает невалидный email формата `not-an-email` и возвращает статус 201 (Created), хотя должна вернуть ошибку валидации 422 (Unprocessable Entity) или 400 (Bad Request).

**Детальное описание:**  
Система не выполняет валидацию формата email при регистрации пользователей. Это позволяет создавать пользователей с некорректными email адресами, что может привести к проблемам:
- Невозможность восстановления пароля
- Проблемы с уведомлениями
- Нарушение бизнес-логики (email должен быть уникальным и валидным)

**Шаги для воспроизведения:**
1. Выполнить POST запрос на `/api/v1/auth/register`
2. Отправить JSON payload с невалидным email: `"email": "not-an-email"`
3. Проверить статус ответа

**Ожидаемый результат:**  
Статус 422 (Unprocessable Entity) или 400 (Bad Request) с описанием ошибки валидации email в формате:
```json
{
  "detail": "Invalid email format"
}
```

**Фактический результат:**  
Статус 201 (Created), пользователь успешно создан:
```json
{
  "id": 123,
  "email": "not-an-email",
  "status": "created"
}
```

## БАГ-РЕПОРТ #2

### Базовая информация

**ID бага:** `BUG-USER-PHONE-VALIDATION`  
**Название:** Регистрация пользователя с телефоном, содержащим буквы, проходит успешно  
**Дата обнаружения:** 2025-10-30  
**Обнаружен:** Directpi  
**Приоритет:** P1 (High)  
**Серьезность:** High  
**Статус:** New  
**Исполнитель:** Не назначен  
**Окружение:** DEV  
**Версия API:** v1  
**Модуль:** Auth / User

---

### Описание

**Краткое описание:**  
При регистрации нового пользователя через эндпоинт `/api/v1/auth/register` система принимает телефонный номер, содержащий буквы (например, `+7ABCDEF1234`), и возвращает статус 201 (Created), хотя должна вернуть ошибку валидации 422 (Unprocessable Entity) или 400 (Bad Request).

**Детальное описание:**  
Система не выполняет валидацию формата телефонного номера при регистрации пользователей. Телефонный номер должен содержать только цифры и допустимые символы (+, -, скобки, пробелы), но не буквы. Это может привести к проблемам:
- Невозможность отправки SMS-уведомлений
- Проблемы с интеграцией с внешними сервисами (GLONASS, платежные системы)
- Нарушение бизнес-логики (телефон должен быть уникальным и валидным)

**Шаги для воспроизведения:**
1. Выполнить POST запрос на `/api/v1/auth/register`
2. Отправить JSON payload с телефоном, содержащим буквы: `"phone": "+7ABCDEF1234"`
3. Проверить статус ответа

**Ожидаемый результат:**  
Статус 422 (Unprocessable Entity) или 400 (Bad Request) с описанием ошибки валидации телефона в формате:
```json
{
  "detail": "Invalid phone format. Phone should contain only digits and allowed characters"
}
```

**Фактический результат:**  
Статус 201 (Created), пользователь успешно создан:
```json
{
  "id": 124,
  "phone": "+7ABCDEF1234",
  "status": "created"
}
```
