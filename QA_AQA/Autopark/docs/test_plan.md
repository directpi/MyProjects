**Автор:** QA Team

## 1. Обзор

### 1.1 Цель документа
Данный документ описывает план тестирования для системы управления автопарком, включая веб-интерфейс, REST API и телеграм-бот.

### 1.2 Область тестирования
- REST API (FastAPI) - основной фокус
- Интеграции: PostgreSQL, Minio
- Авторизация и безопасность
- Бизнес-логика: управление пользователями, транспортными средствами, заказами

### 1.3 Область тестирования
- ✅ REST API (FastAPI) - **100% покрытие эндпоинтов** (105/105 методов)
- ✅ UI тестирование - реализовано (13+ тестов, Page Object Model)
- ✅ Интеграционное тестирование - GLONASS, MinIO, System
- ✅ Нагрузочное тестирование - базовое покрытие реализовано (см. `performance_test_plan.md`)
- ⚠️ Телеграм-бот - тестирование на отдельном этапе

---

## 2. Подход к тестированию

### 2.1 Типы тестирования

#### 2.1.1 Функциональное тестирование
- **Smoke тесты** - критичные бизнес-потоки
- **Sanity тесты** - базовые проверки после изменений
- **Регрессионное тестирование** - проверка ранее работающего функционала
- **API тестирование** - полное покрытие эндпоинтов

#### 2.1.2 Нефункциональное тестирование
- **Безопасность** - авторизация, валидация, OWASP Top 10
- **Интеграционное** - проверка взаимодействия с БД и Minio
- **Производительность** - время отклика критичных эндпоинтов

#### 2.1.3 Специальные типы
- **Негативное тестирование** - обработка ошибок
- **Граничные значения** - валидация границ
- **Тестирование восстановления** - обработка сбоев

### 2.2 Стратегия тестирования
Подробности см. в документе `test_strategy.md`

## 3. Критерии входа и выхода

### 3.1 Критерии входа (Entry Criteria)
- ✅ API сервер развернут и доступен
- ✅ Тестовое окружение настроено (dev/staging)
- ✅ Тестовые данные подготовлены
- ✅ Доступ к БД и Minio настроен
- ✅ Переменные окружения сконфигурированы (`.env`)
- ✅ Автотесты проверены на синтаксические ошибки

### 3.2 Критерии выхода (Exit Criteria)
- ✅ Все smoke тесты пройдены (100%)
- ✅ Критичные баги закрыты (P0, P1) - 2 известных бага документированы (BUG-USER-EMAIL-VALIDATION, BUG-USER-PHONE-VALIDATION)
- ✅ **Покрытие тестами: 100% эндпоинтов из OpenAPI схемы** (105/105 методов)
- ✅ Автоматизированные тесты стабильны (процент прогонов ≥ 95%)
- ✅ Документация по багам актуализирована

## 4. Расписание и ресурсы

### 4.1 Этапы тестирования

#### Фаза 1: Smoke тестирование (1-2 дня)
- Базовая проверка доступности API
- Авторизация и регистрация
- Критичные CRUD операции (User, Vehicle)

#### Фаза 2: Функциональное тестирование (5-7 дней)
- Полное покрытие API эндпоинтов
- Валидация и обработка ошибок
- Интеграционное тестирование

#### Фаза 3: Регрессионное тестирование (2-3 дня)
- Повторный прогон всех тестов
- Проверка фиксов багов

#### Фаза 4: Безопасность и производительность (3-4 дня)
- Security тестирование
- Проверка производительности

### 4.2 Ресурсы
- **QA инженер:** 1 человек
- **Окружение:** dev/staging серверы
- **Инструменты:** pytest, requests, PostgreSQL клиент, Minio клиент

## 5. Тестовые сценарии и приоритеты

### 5.1 Критический приоритет (P0)
1. Авторизация и регистрация
2. CRUD операции User
3. CRUD операции Vehicle
4. Healthcheck

### 5.2 Высокий приоритет (P1)
5. Управление заказами (Logist Order, Driver Order)
6. Обслуживание транспорта (Vehicle Maintenance)
7. Интеграция GLONASS

### 5.3 Средний приоритет (P2)
8. Отчетность
9. Финансовые операции (Payment, Salary)
10. Файловые операции (Minio)

### 5.4 Низкий приоритет (P3)
11. Справочники (User Role, Vehicle Type)
12. Административные функции

Подробные тест-кейсы см. в `test_cases.md`

## 7. Окружения и конфигурация

### 7.1 Тестовые окружения
- **DEV** - для разработки и первоначального тестирования
- **STAGING** - для полного прогона тестов перед релизом

### 7.2 Конфигурация
- Все настройки хранятся в `.env` файлах
- Раздельные конфиги для разных окружений
